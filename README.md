# AstrBot Portfolio

AstrBot QQ 群股票持仓记账插件。群成员可以登记自己的股票持仓、记录买卖、查看其他已登记成员的持仓，以及查看全群持仓汇总。

**本插件只管理用户自行填写的账本数据，不连接券商账户，也不会实际下单。**

## 功能

- **个人持仓**：设置初始持仓、买入、卖出；按移动平均成本法计算剩余成本和已实现盈亏。
- **持仓周期与摊薄成本**：将当前持仓周期内所有已实现盈亏计入摊薄成本，公开显示周期已实现及综合盈亏，逐笔交易历史仍仅本人可见。
- **自然语言记账**：使用 `/持仓 记` 将一条明确的成交描述交给当前会话的 LLM 解析；校验通过后直接记账并返回回执。
- **一键撤回 / 恢复**：`/持仓 撤回` 切换本人在当前群最近一次成功输入的生效状态。连续发送可撤回、恢复、再次撤回。
- **群内公开查询**：查看同群已登记成员的持仓；通过固定 `#编号` 查询，避免依赖 QQ 平台的 @ 兼容性。
- **成员名单和群汇总**：列出当前仍有持仓的登记成员，按股票和币种汇总持有人数、数量及加权平均成本。
- **交易历史**：本人可查看最近的设置及买卖记录，并区分已撤回与生效中的输入。
- **数据持久化**：使用 SQLite，支持消息去重、事务回滚和既有数据库版本迁移。

## 安装

将仓库克隆到 **AstrBot 的持久化 `data/plugins/` 目录**：

~~~bash
cd /path/to/astrbot/data/plugins
git clone https://github.com/aaeviru/astrbot_plugin_portfolio.git
~~~

目录结构应类似：

~~~text
data/
├── plugins/
│   └── astrbot_plugin_portfolio/
│       ├── main.py
│       ├── metadata.yaml
│       ├── identity.py
│       ├── models.py
│       ├── services/
│       └── repositories/
└── plugin_data/
    └── astrbot_plugin_portfolio/
        └── portfolio.db
~~~

`plugin_data/astrbot_plugin_portfolio/portfolio.db` 会在插件初始化时自动创建，**不要将源码放进 `plugin_data/`**。

对于群晖 NAS / Docker 部署，请将代码放在容器 **`data` 卷对应的宿主机目录** 下，而不是一个会随容器重建而消失的临时目录。

在 AstrBot WebUI 的插件管理中重载插件（或重启 AstrBot），然后在 QQ 测试群执行：

~~~text
/持仓 身份
/持仓 帮助
~~~

插件使用 Python 标准库 SQLite、Decimal 等组件，不需要额外安装第三方 Python 依赖。

### 自然语言功能的前提

先在 AstrBot 中为当前 QQ 会话配置可用的 **聊天模型提供商**。只有 `/持仓 记` 会使用该模型；精确买卖、查询、群汇总和撤回均不需要 LLM。

## AKShare MCP 最新行情与浮动盈亏

本插件可复用 AstrBot 已连接的 **AKTools（AKShare）MCP**，在 `/持仓 查看` 和 `/持仓 汇总` 时显示**最新可用股价、市值、未实现盈亏、盈亏率**。行情查询不调用 LLM，不修改原有交易和持仓记录。

**当前仅支持沪深 A 股（例如 `600519.SH`、`000001.SZ`）**。美股、日股、港股仍可照常记录和查询成本，但会标注行情暂未接入；不会混合不同币种计算总收益。

使用前请在 AstrBot 的 MCP 服务列表中添加并连接官方 [AKTools](https://github.com/akfamily/aktools) MCP，服务器名称建议包含 `aktools` 或 `akshare`，工具列表应提供 `get_data`。插件只调用已连接的 MCP 客户端，无需在 AstrBot 容器内另装 AKShare。

行情通过 `stock_individual_info_em` 获取，单只报价缓存约 90 秒、单次最多请求 8 只；交易所休市、服务延迟或数据源不可用时不会凭空补价。**回复中的抓取时间不是交易所成交时间**，标示的“最新可用价”不等于可立即成交的价格。

计算公式：**浮盈亏 = 股数 × 最新可用价 − 剩余持仓总成本**，收益率 = 浮盈亏 ÷ 剩余成本 × 100%。已实现交易盈亏仍按卖出时的记账规则计算。

详见 [行情与浮动盈亏说明](docs/QUOTES.md) 及 [摊薄成本与综合盈亏规则](docs/COST_BASIS.md)。

## QQ 指令

以下命令在**群聊**中使用；股数为整数，单价为每股价格。

| 指令示例 | 作用 |
| --- | --- |
| `/持仓 设置 600519.SH 100 1500` | 校准当前持仓：贵州茅台 100 股，平均成本 1500 CNY |
| `/持仓 买入 9432.T 200 165.7` | 追加买入 NTT 200 股，单价 165.7 JPY |
| `/持仓 卖出 9432.T 100 170` | 卖出 NTT 100 股，计算本次已实现盈亏 |
| `/持仓 记 今天165.7日元买了200股NTT` | 调用 LLM 解析一笔已完成的操作，校验后立即入账 |
| `/持仓 撤回` | 撤销本人当前群的最新一笔成功输入；再次执行则恢复 |
| `/持仓 查看` | 查看本人持仓 |
| `/持仓 查看 #1` | 查看本群登记编号 #1 的持仓 |
| `/持仓 查看 用户ID` | 按当前平台的用户 ID 查询同群登记持仓 |
| `/持仓 名单` / `/持仓 名单 2` | 查看本群有持仓的登记用户（分页） |
| `/持仓 汇总` / `/持仓 汇总 2` | 查看本群按标的汇总的持仓（分页） |
| `/持仓 历史` | 查看本人最近的记账历史 |
| `/持仓 身份` | 查看当前平台、群、用户及登记编号 |
| `/持仓 帮助` | 显示插件内置帮助 |

支持代码示例：`600519.SH`（A 股）、`9432.T`（日股）、`NVDA`（美股）。实际股票代码格式由代码中的校验规则决定，当前不提供证券代码或上市状态的实时核验。

### 摊薄成本与综合盈亏

- **移动平均成本不变**：未来买卖仍按原有剩余持仓成本计算，摊薄成本只用于展示。
- **周期已实现盈亏**：当前持仓周期内全部有效部分卖出的已实现盈亏。`SET` 校准或完整清仓结束旧周期，重新买入后从零开始。撤回/恢复会相应重新计算。
- **摊薄成本**：`(剩余持仓总成本－当前周期已实现盈亏) / 当前股数`，可为负。
- **综合盈亏**：`持仓浮盈亏＋当前周期已实现盈亏`。不重复计算已抵扣在摊薄成本中的收益。
- `/持仓 查看 #编号` 和 `/持仓 汇总` 公开这些汇总数值；`/持仓 历史` 仍仅本人可见。
- 如果没有可用行情，依旧显示摊薄成本和周期已实现；综合盈亏标为暂不可计算。群内跨币种不合计，亦不显示容易产生歧义的综合收益率。

### 记账规则

- `设置`（SET）是**覆盖式持仓校准**，不是一次真实买卖，不生成已实现盈亏。
- `买入`（BUY）追加持仓数量和成本；`卖出`（SELL）按移动平均成本法扣除剩余成本并计算已实现盈亏。
- 成本内部用 Python `Decimal` 计算；SQLite 以十进制字符串保存成本。界面显示金额时可能保留两位小数。
- 暂不支持碎股、手续费、税费、股息、拆股和自动汇率折算；群汇总中的成本也不是实时市值。

### 自然语言记账与撤回

**自然语言记账是“解析 → 校验 → 立即写入 → 回复结果”，不是待确认草稿。** 模型不具备直接执行数据库命令的权限，持仓所属用户来自当前 AstrBot 消息事件，不能由模型指定。对于计划、假设、尚未成交或缺少必要信息的描述，插件会拒绝记账；对于模型已经接受的描述，请务必核对机器人回执。

`/持仓 撤回` 的规则刻意保持简单：

1. 每位用户在每个群中，只有**最后一次成功提交的持仓输入**可以撤回。
2. 第一次撤回恢复该输入前的持仓快照；再次撤回恢复输入后的快照。
3. 新的 `设置`、`买入`、`卖出` 或自然语言记账会替换可撤回目标；**没有多级撤销栈**。
4. 查询和撤回操作自身不改变“最新输入”；重复投递的同一 QQ 消息不会重复切换。
5. 以前的已撤回记录仍保留在历史中；不支持按交易编号撤销更早的历史记录。

## 权限与 QQ 平台兼容性

- 只支持群聊。写入与撤回仅作用于**消息发送者自己**的持仓，身份键为 `(platform_id, group_id, user_id)`。
- 同一群中，其他成员可以读取已登记持仓；不能跨群读取或修改其他人的持仓。`/持仓 历史` 为本人查询。
- `/持仓 名单` 是**当前仍持有股票的登记用户**目录，不等于 QQ 平台实时群成员名单；清仓后原编号仍保留。
- OneBot / aiocqhttp 的结构化 @ 可能被识别为查询目标；QQ 官方机器人不保证提供相同形式。推荐优先使用 `/持仓 名单` 和 `/持仓 查看 #编号`。
- 同一来源消息 ID 会去重；买卖、历史及撤回状态在 SQLite 事务中保持一致。

## 数据存储与升级

数据库默认路径：

~~~text
data/plugin_data/astrbot_plugin_portfolio/portfolio.db
~~~

主要表：

| 表 | 作用 |
| --- | --- |
| `holdings` | 当前持仓数量与剩余总成本 |
| `trades` | 历史 SET / BUY / SELL 输入及其生效状态 |
| `portfolio_members` | 群内登记编号与昵称快照 |
| `latest_input` | 本人当前群最新输入的操作前后快照 |
| `toggle_events` | 撤回 / 恢复消息去重与事件记录 |
| `seen_parse_requests` | 兼容旧版本的自然语言请求去重信息 |

当前 SQLite 数据结构版本为 **`PRAGMA user_version = 4`**，支持旧版本数据库升级。v3 的未入账确认草稿在升级时会移除；由于旧交易没有完整的操作前快照，**只能撤回升级后新产生的输入**。

更新插件前请备份 `portfolio.db`；不要提交数据库文件到 Git。

## 开发和测试

在本仓库的**父目录**执行：

~~~bash
python -m unittest discover -s astrbot_plugin_portfolio/tests -v
~~~

GitHub Actions 会在 push / PR 时运行 Python 3.11 的离线测试。测试覆盖成本计算、买卖、事务、数据库迁移、身份隔离、QQ 消息模拟、自然语言解析和最新输入撤回 / 恢复。

自动化测试不等于真实 QQ 平台与 LLM Provider 的端到端验证，正式使用前建议先在测试群试运行。
