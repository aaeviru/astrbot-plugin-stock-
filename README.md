# 群友持仓记录（AstrBot）

第七讲教学版 **v0.3.0**：QQ 群内自主登记股票持仓、公开查询、全群汇总，以及**自然语言直接记账 + 本人最新输入撤回/恢复**。本插件**不连接券商、不执行证券交易**。

仓库：https://github.com/aaeviru/astrbot-plugin-stock-

## 快速使用

```text
/持仓 设置 9432.T 100 150
/持仓 买入 9432.T 200 165.7
/持仓 卖出 9432.T 100 170
/持仓 记 今天165.7日元买了200股NTT
/持仓 撤回              # 撤销本人在当前群的最后一次持仓输入
/持仓 撤回              # 再执行一次，恢复刚才那次输入
/持仓 查看              # 自己的持仓
/持仓 查看 #1           # 公开查询登记用户编号
/持仓 查看 用户ID        # 同群公开查询
/持仓 名单 [页码]
/持仓 汇总 [页码]
/持仓 历史
/持仓 身份
/持仓 帮助
```

`/持仓 记` **只在用户主动使用此指令时调用一次 LLM**。成功识别单笔已完成的买卖或明确的持仓设置后，直接执行 SQLite 事务并回复记录结果；**不再询问确认码**。若识别失败或存在计划、假设、未成交、缺少股数/价格等情况，拒绝记账。模型可能误解人类表达，收到回复时应核对价格、代码和数量；有误可立即 `/持仓 撤回`。

`/持仓 撤回` 无时间限制、无编号、无二次确认。它永远只切换**同一平台、同一群、同一发送者最后一次成功的 SET/BUY/SELL/自然语言记账**。每个用户在每个群里只有一个可切换的目标；连续不同的撤回消息在「已撤销 ↔ 已恢复」间切换，不会回退到更早的输入。**新输入会替换切换目标**，如果之前的输入已撤销，它仍保持已撤销。查询、名单和撤回本身不改变目标。旧输入错误请用 `/持仓 设置` 校准。

`/持仓 设置` 是持仓覆盖校准，不是实际买卖；`/持仓 买入`/`卖出` 使用移动平均成本法。不处理手续费、税、拆股、碎股、跨币种折算、实时行情等。`/持仓` 根命令展示命令树，不等同于 `/持仓 查看`。

## 安装

克隆到 AstrBot 的插件目录（目录名须为 `astrbot_plugin_portfolio`），然后通过 WebUI 重载。

```sh
git clone https://github.com/aaeviru/astrbot-plugin-stock-.git astrbot_plugin_portfolio
```

GitHub PR 中的新版本如尚未合并，请检出 PR 分支后再测试（不要把测试版直接覆盖生产数据）。NAS/Docker 的 AstrBot `data` 应配置持久化存储。数据库默认位于 `data/plugin_data/astrbot_plugin_portfolio/portfolio.db`。不需额外 Python 依赖。

## 安全和权限

- 写入身份来自 `get_platform_id()` + `get_group_id()` + `get_sender_id()`；所有普通/AI 写入与撤回都只能操作**消息发送者本人**，不能由命令选择他人。
- 读取可以指定同群其他人，但不能指定其他群。`#编号` 是公开查询别名，不是写入权限凭据。
- 只在群聊使用。公开数据是群友自愿登记的信息，未核验券商账户。
- OneBot 可能提供可识别的结构化 @；QQ 官方机器人可能没有，建议使用 `/持仓 名单` 和 `/持仓 查看 #编号`。
- LLM 不获得数据库工具；只负责提取 JSON，Python 检查严格字段、证券代码、十进制价格、数量和基本的非成交措辞。自然语言解析并非绝对正确，务必看机器人回执。
- 同一来源消息 ID 不会重复入账或重复切换；事务提交保持持仓/历史/撤回标记一致。

## 数据模型与迁移

- `holdings`：当前持仓（总成本以 Decimal 字符串保存）。
- `trades`：每次成功 SET/BUY/SELL 的历史，`is_active` 标识这笔输入是否被撤回。
- `portfolio_members`：群内稳定编号与昵称快照。
- `latest_input`：每个 `(platform_id, group_id, user_id)` 一条，保存**最新输入**操作前后快照与生效状态。
- `toggle_events`：只用于去重和审计撤回消息；**撤回不会成为新交易，也不会进入撤销栈**。
- `seen_parse_requests`：保留兼容旧版 v3 的重复消息数据，不在新流程生成待确认草稿。

`PRAGMA user_version = 4`。可从 v1/v2/v3 自动升级，原持仓及交易历史保留。旧 v3 `pending_actions` 是未入账草稿，升级时会**删除该表**，以前的确认码不可再用；旧交易没有可靠的前态快照，因此**只有升级后新提交的输入才能通过 `/持仓 撤回` 切换**。在 NAS 上升级前请备份 `portfolio.db`；不要将 `.db` 文件提交 Git。

## 测试

在插件目录的**父目录**：

```sh
python -m unittest discover -s astrbot_plugin_portfolio/tests -v
```

测试涵盖移动平均成本、事务回滚、历史保留、消息幂等、公开查询、跨群/用户隔离、连续撤回/恢复、新输入覆盖撤回目标、重启后恢复，以及模拟 AstrBot LLM Provider 与 Handler。测试不等于真实 QQ 接入的端到端验证；生产群部署前请先用测试群确认效果。
